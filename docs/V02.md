# Lavertia v0.2 Playground preview

This branch uses lavertia/support feat/component-protocol-v1 and lavertia/panels feat/tables-forms-i18n-v02.

## Routes

- /admin/dashboard: local search, select filters, toggleable columns, keyboard-accessible column reordering, local page slicing, and a form preview.
- /admin/model-demo: actual scoped Eloquent query with database pagination, search, sorting, and exact-match filter. Only the authenticated user's account is visible.

Both routes require authentication.

## Locale testing

Visit /admin/dashboard?lang=en, ?lang=ar and ?lang=fr. ResolveLocale stores validated locale in the Laravel session. PHP labels come from Laravel translation files, and Lavertia main content sets Arabic dir=rtl. The outer Starter Kit sidebar is not fully localized or RTL yet.

## What is deliberately not implemented

- Form submit is disabled, with no server persistence, Laravel Form Requests, or mutation actions.
- Remote API pagination adapters are not implemented. External data can be mapped to safe bounded Table::rows() snapshots on the Laravel server.
- Column visibility/order preferences are not persisted between visits.
- Row reordering, relationship editing, repeaters, wizard steps, file uploads, export and bulk actions are not yet available.

## CI / QA gates

- Panels CI checks PHP syntax and Vite compilation for React, Vue, Svelte.
- Playground static CI checks code and environment-file safety.
- Laravel/Pest, TS checks and application builds need LAVERTIA_READ_TOKEN with read access to private support and panels repositories. A skipped job is not a passing integration test.
- After running integration CI, manually check keyboard use, 320px mobile, dark/light mode, Arabic RTL and 200% zoom.

Always scope Eloquent queries to the authenticated user's tenant and enforce Laravel policies before fetching or changing data. UI column visibility is not a security feature.

## Persisted Form demonstration (development branch)

The Dashboard demo now posts to a Laravel `web` + `auth` route using Inertia. It persists validated `display_name`, `role`, `bio` and `notify` values to a user-owned row through an Eloquent relationship. No arbitrary model attributes or user IDs are accepted. CSRF protection is Laravel's normal web/session middleware. The UI supports POST/PUT/PATCH at the component-protocol level; the demo uses POST.

PHP feature tests cover anonymous access, invalid input, cross-user payload injection, and updates. Integration CI remains gated by cross-repository access while these repositories are private.

### Secure form endpoint

The example route accepts POST, PUT and PATCH, with Laravel web-session CSRF, `auth`, `verified` middleware, an explicit `SaveDemoProfileRequest` validator, an ownership `LavertiaDemoProfilePolicy` and database uniqueness for user-owned records. Tests exercise denied guest/unverified requests, disallowed roles, unrelated user IDs, PATCH/PUT and repeat updates.
