# Lavertia v0.2 Playground preview

This branch integrates the **public** `lavertia/support`, `lavertia/panels`, `lavertia/forms` and `lavertia/tables` repositories. Their integration branches have been merged; CI checks out their `main` branches. This is a development preview, **not a tagged release**.

## Routes

- `/admin/dashboard`: local search, select filters, toggleable columns, keyboard-accessible column reordering, local page slicing and form components.
- `/admin/model-demo`: an authenticated, user-scoped Eloquent query with database pagination, search, sorting and exact-match filtering.

Both routes require authentication. The model demo is an application-controlled sample, not a general-purpose unscoped query executor.

## Locale testing

Visit `/admin/dashboard?lang=en`, `?lang=ar` and `?lang=fr`. `ResolveLocale` accepts supported languages and stores the chosen locale in the session. PHP labels come from Laravel translation files. Lavertia content uses RTL direction in Arabic; the surrounding Starter Kit navigation is not fully localized/RTL.

## Persisted form demonstration

The dashboard uses Inertia submissions to an explicit Laravel route protected by `web`, `auth` and `verified` middleware. A `SaveDemoProfileRequest` validates `display_name`, `role`, `bio` and `notify`. The controller saves through an authenticated-user Eloquent relationship, checks the `LavertiaDemoProfilePolicy`, and relies on database uniqueness for a user-owned profile. The endpoint supports POST, PUT and PATCH; the demo uses POST.

Forms without an action remain previews. Form validation and authorization always run on the Laravel server. Inertia validation errors are rendered by the adapters. The server does not trust a supplied user ID or arbitrary model attributes.

## Canonical Forms / Tables packages

The PHP `lavertia/forms` and `lavertia/tables` descriptors are separate Composer packages. For compatibility, Panels keeps aliases for the previous `Lavertia\\Panels\\Components\\*` classes. Integration tests assert the legacy aliases resolve to canonical component classes and produce compatible serialized payloads.

The CI workspace checks out all four public packages as siblings of `playground/`, installs **committed Composer locks** with `composer install`, and runs PHP/Pest, TypeScript type-checking and production builds on React, Vue and Svelte.

## Laravel Modular host application support

The canonical `lavertia/panels` package also supports module-owned Pages from Composer PSR-4 packages such as `internachi/modular`. A module provider registers its Pages with `PanelRegistry::discoverPages()` for an existing Panel; this preserves the host's authentication middleware and avoids conflicting with broad team routes. The integration is tested using an installed Laravel 13 module before and after route caching. See the [Panels Laravel Modular guide](https://github.com/lavertia/panels/blob/main/docs/MODULAR_LARAVEL.md).

This is an optional host application integration; no `internachi/modular` dependency is required by the Playground's canonical v0.2 Composer packages. A separate Playground PR adds Vite full-browser refresh for module-owned PHP files.

## Quality and release gates

- The `Playground CI` workflow must pass **Source validation** and all three real **Laravel + stack** jobs. A skipped integration job is not a pass.
- All source repositories are public; a private package read token is no longer needed for these checkout steps.
- Composer lockfiles for React, Vue and Svelte were regenerated from the public canonical packages, committed as [00961877](https://github.com/lavertia/playground/commit/009618770a7961726f9c32467f3693e4fd31e08d), and verified using `composer validate --strict --no-check-publish` plus `composer install`.
- The one-off, branch-limited GitHub Actions workflow used to regenerate locks was removed after the commit. Release CI now requires strict lockfile validation and reproducible install; **keep this gate green** before merging or tagging.
- The tag release gate rejects failed or skipped integration and validates committed locks. A green untagged branch is not evidence of a tagged release test or manual browser QA.
- Manual QA remains required: keyboard operation, 320px mobile viewport, light/dark themes, Arabic RTL, 200% zoom and error/empty/loading states.
- **No v0.2 stable tag is approved.**

## Known exclusions

- No remote API pagination adapter; server-side Table snapshots must be bounded.
- No persisted column order/visibility preferences.
- No row reordering, relationship editing, repeaters, wizard steps, file upload, export or bulk actions.

Always authorize and scope the Eloquent query to the authenticated user/tenant **before** search, ordering or pagination. UI column visibility never replaces field-level authorization.
